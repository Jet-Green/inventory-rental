# Правовые документы платформы «Аренда инвентаря»

> Все документы в этой папке — **шаблоны**, подготовленные для последующей
> проверки практикующим юристом. До проверки юристом публиковать на боевом
> сайте нельзя. Чеклист для юриста — в конце этого файла.

## 1. Карта документов: что и где показывать

| Файл | Документ | Где показывать на сайте |
|---|---|---|
| `polzovatelskoe-soglashenie.md` | Пользовательское соглашение | Футер (постоянная ссылка); чекбокс «Принимаю условия» при **регистрации** любого пользователя |
| `politika-konfidencialnosti.md` | Политика обработки ПДн (152-ФЗ) | Футер; ссылка рядом с любой формой, собирающей данные (регистрация, верификация, обратная связь); cookie-баннер |
| `soglasie-na-obrabotku-pd.md` | Согласие на обработку ПДн | Отдельный **непредвыбранный** чекбокс при регистрации; повторно — при верификации арендатора (ввод паспорта) и при заполнении данных организации. Отдельный второй чекбокс — рекламная рассылка |
| `agentskiy-dogovor-oferta.md` | Агентский договор-оферта (площадка ↔ арендодатель) | Футер; чекбокс-акцепт при регистрации роли «business» / создании организации и при публикации первого объявления |
| `publichnaya-oferta.md` | Публичная оферта услуг площадки (площадка ↔ арендатор) | Футер; ссылка + чекбокс на странице **checkout** (оформление/оплата бронирования) |
| `dogovor-arendy.md` | Шаблон договора аренды (арендодатель ↔ арендатор) | Не публичная страница, а **шаблон генерации PDF**: показывать превью на checkout до оплаты («ознакомьтесь с договором»), готовый PDF — в личном кабинете обеих сторон после подтверждения брони |

Схема пакета: агентский договор покрывает отношения с арендодателем (принципалом),
публичная оферта — с арендатором, пользовательское соглашение — общие правила.
Если юрист решит упростить, `publichnaya-oferta.md` можно влить в пользовательское
соглашение (комментарий об этом — в шапке самого файла оферты).

### 2.3. Расхождения шаблонов с текущей генерацией PDF

Текущий `contract-pdf.service.ts` генерирует сильно упрощённые версии договора
аренды (5 разделов) и агентского договора (4 раздела). Шаблоны в этой папке —
полные версии. При внедрении:

1. Либо расширить `generateRentalAgreement`/`generateAgencyAgreement` до полных
   текстов из шаблонов, либо принять, что PDF — «краткая форма», а полные
   условия инкорпорируются ссылкой на оферты сайта (юристу решить допустимость).
2. `ContractParty` не содержит `email` и `passport` — для полного шаблона
   договора аренды их нужно добавить в интерфейс и пробрасывать из User.
3. Комиссия в коде захардкожена `totalPrice * 0` — при вводе реальной комиссии
   синхронизировать с п. 4.1 агентского договора.

## 3. ЧЕКЛИСТ для живого юриста перед публикацией

**Модель посредничества и договорная схема**
- [ ] Подтвердить модель агента: от своего имени или от имени принципала (ст. 1005 ГК РФ) — в шаблонах заложена схема «от своего имени, за счёт принципала» с оговоркой; выбрать одну и убрать альтернативу во всех документах.
- [ ] Проверить, не образует ли деятельность площадки признаки платёжного агента по 103-ФЗ «О приёме платежей…» (приём денег физлиц в пользу третьих лиц): риски спецсчёта, ККТ платёжного агента. Возможно, безопаснее номинальный счёт или расчёты напрямую через эквайринг с разделением платежей (сплитование).
- [ ] Оценить применимость § 2 гл. 34 ГК РФ «Прокат» (ст. 626–631): прокат применяется, когда арендодатель-предприниматель сдаёт имущество в качестве постоянной деятельности; для арендодателей-физлиц действует общая аренда. В шаблоне договора это условное разветвление (п. 1.3) — проверить формулировку.
- [ ] Для арендаторов-потребителей: проверить все ограничения ответственности на соответствие ст. 16 Закона «О защите прав потребителей» (ничтожность ущемляющих условий).

**Электронное заключение договоров**
- [ ] Проверить конструкцию простой электронной подписи (63-ФЗ): достаточность соглашения о ПЭП в пользовательском соглашении, идентификация подписанта, фиксация логов (кто, когда, что подтвердил).
- [ ] Договор аренды между двумя пользователями заключается «через платформу» — проверить, корректно ли оформлен обмен акцептами между самими сторонами (а не только с площадкой).

**Налоги, ККТ, платежи**
- [ ] Определить, кто выдаёт кассовый чек арендатору (агент на УСН/ИП, арендодатель-самозанятый через «Мой налог», и т.д.) — 54-ФЗ.
- [ ] Проверить НДФЛ-риски: не становится ли площадка налоговым агентом при выплатах арендодателям-физлицам (ст. 226 НК РФ) — критично для схемы «агент от своего имени».
- [ ] Прописать работу с самозанятыми-арендодателями (НПД, 422-ФЗ), если они допускаются.
- [ ] Согласовать размер комиссии, сроки выплат, правила отмены/возвратов (сейчас — плейсхолдеры).

**Персональные данные (152-ФЗ)**
- [ ] Подать/проверить уведомление оператора в Роскомнадзор (ст. 22 152-ФЗ).
- [ ] Проверить актуальную редакцию 152-ФЗ на дату публикации (требования к согласиям, оборотные штрафы за утечки, локализация БД в РФ).
- [ ] Утвердить перечень обработчиков (хостинг, эквайринг, рассылки) и наличие договоров-поручений с ними.
- [ ] Отдельное согласие на рекламные рассылки — непредвыбранный чекбокс (38-ФЗ «О рекламе»).
- [ ] Хранение паспортных данных арендаторов: оценить необходимость/минимизацию, режим защиты (это чувствительный объём ПДн).
- [ ] Назначить ответственного за обработку ПДн, издать внутренние локальные акты.

**Тексты и реквизиты**
- [ ] Заполнить все плейсхолдеры из таблицы 2.2 реальными значениями; убедиться, что в опубликованных версиях не осталось `{{...}}`.
- [ ] Проверить преамбулы для трёх статусов сторон (физлицо/ИП/ООО), включая подписанта ООО и основание полномочий.
- [ ] Решить вопрос залога: добавить поле в продукт и раздел 5 договора аренды либо удалить раздел.
- [ ] Проверить подсудность ({{arbitrazh_region}}) и претензионные сроки.
- [ ] Сверить бренд/наименования: «Аренда инвентаря», «Города и Веси» — как соотносятся с юрлицом-владельцем, товарными знаками.
- [ ] Синхронизировать финальные тексты с генерацией PDF в `contract-pdf.service.ts` (см. п. 2.3).
